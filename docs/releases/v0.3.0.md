# Quartermaster 0.3.0

## Changes

- `consult` runs the consumer's native Claude Code in interactive or headless mode.
- Consumers can configure the executable and argument defaults in `claude.json`.
- Arguments after `--` replace the configured Claude arguments without shell interpolation.
- `--context` supplies a complete JSON object for the roster, preferences, and proposed work.
- Both modes receive the same quota evidence and advisory instructions.
- Accepted source documents remain intact alongside normalized display fields.
- `status --json` includes complete source documents under `sources`.
- Headless consultations retain stdout, stderr, exit status, and the dated input packet in private files.
- `--dry-run` prepares the packet without a Claude call.
- Timeouts and termination stop the headless consultation's process group and retain partial output.
- Interactive mode delegates the terminal and session history to Claude Code.
- The repository includes an OpenSpec proposal, requirements, design, implementation tasks, and validation record.

## Use

```sh
# Interactive
quartermaster consult -- --model sonnet

# Headless, with Claude tools disabled
quartermaster consult --headless -- --model sonnet --tools ""

# Inspect the input without a model call
quartermaster consult --context context.json --dry-run -- -p --model sonnet
```

Consultations require an installed, authenticated Claude Code executable.
Quartermaster does not install Claude or choose its authentication method.

## Update

```sh
uv tool install --force https://github.com/goblinmode2700/quartermaster/releases/download/v0.3.0/quartermaster_quota-0.3.0-py3-none-any.whl
```

Existing state files remain readable. Reingest source documents to restore fields discarded by older releases.
Quartermaster preserves the latest document per source, not an unlimited observation history.

CAUTION: Inspect full JSON output before sharing it. It now includes source account identifiers and other source fields.
Running `consult` sends the evidence packet through the consumer's configured Claude provider and consumes its normal allowance.
Consumer Claude permissions control tool access. Advisory instructions are not a security sandbox.

Quartermaster owns `--append-system-prompt-file` for evidence delivery.
Consumer append-prompt flags produce an explicit conflict. Other Claude flags pass through without a version-specific whitelist.

## Scope

The older `advise` command remains a separate, limited heuristic. It is not the Claude adviser.
Consultation prose does not reserve capacity, authorize work, or refresh quota during a conversation.
Collector scheduling, live roster collection, and automatic report delivery remain external integrations.
No live Claude or provider call is part of the automated tests.

## Validation

All 133 tests passed against the installed 0.3.0 wheel outside the checkout on Python 3.13.
Ruff checks, strict OpenSpec validation, and distribution builds passed.
The process tests use a fake Claude executable and real terminal sessions. They do not establish live provider behavior or recommendation quality.
